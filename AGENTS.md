# Git workflow: no pull requests

This is a solo project. Ship finished branches by fast-forwarding straight into `master` and pushing — do not open a GitHub pull request and wait for it to be merged. It's fine to do work in a branch/worktree as usual; once a change is committed and verified, push it directly to `master` instead (e.g. `git push origin <branch>:master`, after confirming a clean fast-forward with `git merge-base --is-ancestor origin/master HEAD`). If `master` has diverged (not a fast-forward), stop and ask rather than force-pushing or merging around the conflict.

**After pushing: also delete the remote copy of the branch you pushed from.** If the working branch (e.g. a `worktree-*` branch from an isolated worktree) was itself pushed to the remote at any point, it lingers there as a stray branch on GitHub even after its content is fast-forwarded into `master` — confirmed 2026-07-26, `origin/worktree-fix-routine-drag-compact` was fully merged into `master` (zero unique commits, verified via `git merge-base --is-ancestor origin/worktree-fix-routine-drag-compact master`) yet still showed up in GitHub's branch list. After a direct push to `master`, run `git push origin --delete <branch>` for the branch you just merged (only the *remote* ref — never delete the local branch itself if a worktree still has it checked out). Skip this if that branch was never pushed under its own name to begin with.

**After pushing: also sync the user's main checkout, not just the remote.** Work usually happens in an isolated worktree (`.claude/worktrees/*`), whose branch is separate from the `master` branch checked out in the user's actual dev checkout (`C:\Users\pavit\OneDrive\Desktop\OpenTracker`) — even though both share the same underlying `.git`, pushing to `origin/master` from a worktree does **not** advance that other checkout's local `master` ref. If you don't pull there too, the user's running Expo/Metro instance keeps serving stale code and any change looks like it "didn't happen," even though it's live on GitHub. So after a direct push to `master`, fast-forward the main checkout as well: `git -C "C:\Users\pavit\OneDrive\Desktop\OpenTracker" pull --ff-only` (check `git -C "<path>" status --short --branch` first — only pull if it's clean and simply behind; if it has diverged or has local changes, stop and ask instead of overwriting).
